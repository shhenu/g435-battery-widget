# G435 Battery Widget

[![Windows build](https://github.com/shhenu/g435-battery-widget/actions/workflows/build.yml/badge.svg)](https://github.com/shhenu/g435-battery-widget/actions/workflows/build.yml)

Микро-виджет для области уведомлений Windows. Показывает примерный заряд
Logitech G435 через обе документированные ревизии LIGHTSPEED-свистка.

## Скачать

[Готовая версия для Windows x64](https://github.com/shhenu/g435-battery-widget/releases/latest).
Скачай ZIP для Windows x64 из раздела Assets, распакуй и запусти
`G435BatteryTrayNative.exe`. Установка дополнительных пакетов не требуется.

## Свистки

| USB-ID | Интерфейс и протокол | Проверка |
| --- | --- | --- |
| `046D:0ADF` | `0xFF00`, 64-байтные пакеты с CRC-16 | Реальный G435 на Windows 10 x64 |
| `046D:0ACB` | `0xFFC0`, report 6, мост Realtek/HDT647: Feature 64 / Output 515 | Записанные пакеты и тесты ошибок; реального свистка у автора нет |

Протокол выбирается автоматически по USB-ID, HID-странице и размерам отчётов.
На неизвестные USB-ID команды не отправляются; сведения о них можно получить
через диагностику. Обычный Bluetooth-адаптер не заменяет LIGHTSPEED-свисток
для этих двух протоколов.

У `0ACB` во время чтения на короткое время прерывается звук. Приложение
отправляет команду выхода из служебного режима также при ошибке или отмене,
до трёх попыток. Если устройство не подтвердило выход, значок предлагает
переподключить свисток.

Для `0ACB` сначала используется 64-байтный Feature-транспорт. Если запрос не
прошёл, служебный режим успешно закрыт и дескриптор поддерживает Output 515,
приложение пробует второй документированный способ обмена. После ошибки
закрытия моста или отмены запроса повторного входа не происходит.

Для Windows 11 используется тот же Win32 API; на Windows 11 отдельно не
проверялся.

## Расход ресурсов

Основная версия написана на C и Win32, без .NET, Python и стандартной библиотеки
C++. Код запуска CRT не используется; проверки стека MSVC сохранены.
Библиотеки для поиска HID-устройства загружаются только на время запроса.

Нативная версия не держит рабочий поток и USB-дескриптор между запросами.
Автообновление выполняется раз в 15 минут. Диагностика работает только при
ручном запуске и не создаёт фонового опроса.

Локальный замер версии 0.2.0 x64: `.exe` — 25 КиБ; после завершения запроса около
6 МБ рабочего набора, 1 МБ приватно выделенной памяти и один поток. В простое
за контрольный замер дополнительного процессорного времени не набралось.

## Сборка

Для лёгкой нативной версии запусти `build-native.bat`. Результат появится здесь:

```text
dist\G435BatteryTrayNative.exe
```

Нужны Visual Studio C++ Build Tools (2019 или новее) с Windows SDK. Установка
находится автоматически через `vswhere`. Для сравнения архитектур
можно собрать `build-lite.bat x64` и `build-lite.bat x86`. Основная сборка — x64:
в локальном сравнении она расходовала меньше памяти, чем x86 через WOW64.

## Использование

1. Подключи LIGHTSPEED-свисток и включи G435.
2. Запусти `G435BatteryTrayNative.exe` (после сборки он находится в `dist`).
3. Найди серую/зелёную иконку батареи в области уведомлений Windows. Если её
   не видно, открой скрытые значки через стрелку `^`.
4. Наведение показывает процент и напряжение. Двойной клик обновляет заряд.
   Правый клик открывает меню обновления, диагностики и выхода.

Опрос выполняется сразу после запуска и затем раз в 15 минут. Процент
рассчитывается по напряжению батареи и может немного колебаться. При зарядке
по USB напряжение растёт, поэтому оценка может быть завышена.

Повторный запуск оставляет один экземпляр виджета. Между запросами приложение
ждёт сообщения Windows; рабочий поток и USB-дескриптор закрываются после
чтения. При выходе во время запроса служебная сессия свистка завершается.

## Проверка из командной строки

```powershell
.\dist\G435BatteryTrayNative.exe --once --json
.\dist\G435BatteryTrayNative.exe --diagnose
.\dist\G435BatteryTrayNative.exe --refresh
.\dist\G435BatteryTrayNative.exe --quit
```

`--once` читает заряд один раз и завершает процесс. `--refresh` и `--quit`
управляют уже запущенным виджетом.

## Если свисток не найден

Если версия 0.2.0 находит интерфейс `0ADF / CRC64`, но показывает таймаут,
обновись до 0.2.1 или новее: исправлена обработка ненулевых служебных байтов
ответа. Сам по себе отчёт диагностики подтверждает только обнаружение USB,
а не успешное чтение заряда.

Распакуй весь релиз и дважды нажми `Diagnose-G435.bat`, либо выбери
«Диагностика» в меню значка. В Блокноте откроется `G435-diagnostics.txt` с
USB-ID, версиями и размерами HID-отчётов. Режим диагностики только читает
метаданные: не включает служебные режимы и не прерывает звук. Серийные номера
и пути устройств в отчёт не попадают.

## Проверка протоколов

```text
test-protocol.bat
```

Тесты не требуют наушников. Они проверяют выбор обеих ревизий, записанные
пакеты, сборку фрагментов PI, повреждённые ответы, ограничение попыток и выход
из моста при ошибке записи, таймауте и отмене. Неизвестные USB-ID и неверные
HID-коллекции должны быть отклонены до отправки команд.

Исходники — `native/G435BatteryTray.c`. В GitHub Actions автоматически собирается
версия x64; полученный `.exe` доступен в артефактах успешного запуска workflow.

Протокол основан на открытых исследованиях G435 и используется только для
чтения состояния батареи. Проект не использует G HUB, DLL Logitech, сеть или
телеметрию.
