# G435 Battery Widget

[![Windows build](https://github.com/shhenu/g435-battery-widget/actions/workflows/build.yml/badge.svg)](https://github.com/shhenu/g435-battery-widget/actions/workflows/build.yml)

Микро-виджет для области уведомлений Windows. Показывает примерный заряд
Logitech G435 через LIGHTSPEED. Сам находит приёмник и выбирает протокол:
USB-ID, отчёты диагностики и ручная настройка для запуска не нужны.

## Скачать

[**Скачать G435BatteryTrayNative.exe для Windows x64**](https://github.com/shhenu/g435-battery-widget/releases/latest/download/G435BatteryTrayNative.exe).

Скачай и запусти этот файл. Установка, Python и дополнительные пакеты не нужны.
Лицензия и сведения об авторах встроены в меню «О программе».

Архив с документацией и необязательной диагностикой — на
[странице последнего выпуска](https://github.com/shhenu/g435-battery-widget/releases/latest).

## Свистки

| USB-ID | Интерфейс и протокол | Проверка |
| --- | --- | --- |
| `046D:0ADF` | `0xFF00`, 64-байтные пакеты с CRC-16 | Реальный G435 на Windows 10 x64 |
| `046D:0ACB` | `0xFFC0`, report 6, мост Realtek/HDT647: Feature 64 / Output 515 | Записанные пакеты и тесты ошибок; реального свистка у автора нет |

Оба известных протокола включены в один `.exe`. Известные USB-ID распознаются
по HID-странице и размерам отчётов. Другой USB-ID также распознаётся, если
устройство сообщает производителя Logitech, модель G435/G435SE и совместимые
параметры управляющего HID-интерфейса. Случайные устройства и неподходящие
HID-коллекции не получают команд.

Если подключено несколько подходящих приёмников, виджет пробует следующий,
когда первый не отвечает. Настраивать выбор вручную не требуется.

Это поддержка двух известных протоколов G435, а не гарантия для будущей
ревизии с другим протоколом. Реального `0ACB` для проверки у автора нет.
Подключение по Bluetooth в этой версии не поддерживается.

У `0ACB` во время чтения на короткое время прерывается звук. Приложение
отправляет команду выхода из служебного режима также при ошибке или отмене,
до трёх попыток. Если устройство не подтвердило выход, значок предлагает
переподключить свисток.

Для `0ACB` сначала используется 64-байтный Feature-транспорт. Если запрос не
прошёл, служебный режим успешно закрыт и дескриптор поддерживает Output 515,
приложение пробует второй документированный способ обмена. После ошибки
закрытия моста или отмены запроса повторного входа не происходит.

Для Windows 11 используется тот же Win32 API; на Windows 11 отдельно не
проверялся.

## Расход ресурсов

Основная версия написана на C и Win32, без .NET, Python и стандартной библиотеки
C++. Код запуска CRT не используется; проверки стека MSVC сохранены.
Библиотеки для поиска HID-устройства загружаются только на время запроса.

Нативная версия не держит рабочий поток и USB-дескриптор между запросами.
После успешного чтения автообновление выполняется раз в 15 минут. Если свисток
или наушники ещё не готовы, повтор происходит через 5, затем 15 и далее
60 секунд. Подключение приёмника и выход Windows из сна запускают новую
проверку. Между попытками приложение ждёт сообщения Windows.

Локальный замер версии 0.3.0 x64: `.exe` — 30 КиБ; после завершения запроса около
6 МБ рабочего набора, 1,05 МБ приватно выделенной памяти и один поток.
За 5 секунд контрольного замера в простое дополнительного процессорного
времени не набралось. Значения зависят от Windows и окружения.

## Сборка

Для лёгкой нативной версии запусти `build-native.bat`. Результат появится здесь:

```text
dist\G435BatteryTrayNative.exe
```

Нужны Visual Studio C++ Build Tools (2019 или новее) с Windows SDK. Установка
находится автоматически через `vswhere`. Для сравнения архитектур
можно собрать `build-lite.bat x64` и `build-lite.bat x86`. Основная сборка — x64:
в локальном сравнении она расходовала меньше памяти, чем x86 через WOW64.

## Использование

1. Запусти `G435BatteryTrayNative.exe`.
2. Подключи LIGHTSPEED-свисток и включи G435 в режиме LIGHTSPEED. Их можно
   подключить и до запуска — порядок не важен.
3. Найди серую/зелёную иконку батареи в области уведомлений Windows. Если её
   не видно, открой скрытые значки через стрелку `^`.
4. Наведение показывает процент и напряжение. Двойной клик обновляет заряд.
   Правый клик открывает меню обновления, диагностики, сведений о программе и выхода.

Первый опрос выполняется сразу после запуска. Процент рассчитывается по
напряжению батареи и может немного колебаться. При зарядке по USB напряжение
растёт, поэтому оценка может быть завышена.

Повторный запуск оставляет один экземпляр виджета. Между запросами приложение
ждёт сообщения Windows; рабочий поток и USB-дескриптор закрываются после
чтения. При выходе во время запроса служебная сессия свистка завершается.

## Проверка из командной строки

```powershell
.\dist\G435BatteryTrayNative.exe --once --json
.\dist\G435BatteryTrayNative.exe --diagnose
.\dist\G435BatteryTrayNative.exe --refresh
.\dist\G435BatteryTrayNative.exe --quit
```

`--once` читает заряд один раз и завершает процесс. `--refresh` и `--quit`
управляют уже запущенным виджетом.

## Если заряд пока не появился

Убедись, что приёмник вставлен в USB, а наушники включены в режиме LIGHTSPEED.
Виджет повторит чтение сам; двойной клик по значку запускает его сразу.
Если другая утилита G435 заняла приёмник, закрой её. Если значок просит
переподключить свисток, вынь его из USB и вставь снова: после неподтверждённого
выхода из служебного режима автоматические попытки останавливаются.

Для обычной работы диагностика не нужна. При желании выбери «Диагностика»
в меню значка или запусти `Diagnose-G435.bat` из архива выпуска.
В Блокноте откроется `G435-diagnostics.txt` с
USB-ID, версиями и размерами HID-отчётов. Режим диагностики только читает
метаданные: не включает служебные режимы и не прерывает звук. Серийные номера
и пути устройств в отчёт не попадают.

## Проверка протоколов

```text
test-protocol.bat
```

Тесты не требуют наушников. Они проверяют выбор обеих ревизий и совместимых
альтернативных USB-ID, отсеивание других моделей и HID-коллекций, переход к
следующему приёмнику и интервалы повторов. Также проверяются записанные
пакеты, номер запроса, сборка фрагментов PI, повреждённые ответы, ограничение
попыток и выход из моста при ошибке записи, таймауте и отмене.

Исходники — `native/G435BatteryTray.c`. В GitHub Actions автоматически собирается
версия x64; полученный `.exe` доступен в артефактах успешного запуска workflow.

Протокол основан на открытых исследованиях G435 и используется только для
чтения состояния батареи. Проект не использует G HUB, DLL Logitech, сеть или
телеметрию.
